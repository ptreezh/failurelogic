## 2. 缺陷清单（重新定级）

### P0-A｜诊断层不可信：输出薄 + 时序错位

两个独立缺陷叠加，必须同批解决，否则修一个反而放大另一个。

**A-1 覆盖薄**：40 条规则中只有 8 条可上屏（20%），实测 5 场景总命中 1 次。
**A-2 时序脱钩（更严重）**：`build(input)` 取**终局** `state`，`buildConcepts` 的 `evalState` = 终局 state + 3 个派生键。因此「命中」的真实语义是「终局数值过了阈值」，**不是**「第 N 回合做了这件事」。若只把派生层做厚而不改求值方式，只会产出更多"看起来连贯但归错回合"的叙事。

修复不是一件事，是**三件不同工种**（这是 v1/v2 前后最大的认知修正）：

| 工种 | 内容 | 量 |
|---|---|---|
| ① 文本工程 | 改写 15 条语法不合规的表达式为 `name op number`（8 条 `atom_shape` + 7 条 `literal_syntax`，含 `%`、引号、中文比较词） | 15 条 |
| ② 代码工程 | 扩派生层：为 17 条缺原子规则提供**回合级**行为指标（`*_count`/`*_lag`/`chose_*`/`turn`），每个值带 `evidence_turn` | ~12 个派生键 |
| ③ 数据工程 | `employee_trust`、`initial_goal_promise` 全库无源；`off_balance_sheet_exposure_usd_m` 单位与阈值量纲不符（规则写 5000，实际单位百万美元）→ 补字段或重标定阈值 | 少数 |

### P0-B｜教育效果不可知（不是"未达成"）

- 无基线、无复测、无跨局对照 → 任何"有改善"都无法证伪。
- 「教育效果未达成」是结论，「不可知」才是事实。前者要靠测量才能说，后者现在就能说。
- **不新建日志系统**：`offline_sessions` 已在盘上，只做聚合视图，避免双写不一致。

## 3. 根因（替换 v1 §3）

> **不是「没接线」，是「写出来的规则与场景数据在类型上不匹配，且没有任何机制会因『诊断输出为 0』而报警」。**

三条支撑：

1. 17 条规则要的是**行为计数**（`deferred_consequence_count`），引擎只产**状态值**（`cash_flow`）—— 类型错配，不是笔误。
2. 15 条规则写成人类可读的自然语言式（`share_price_drop > 50%`），而解析器只吃 `name op number` —— 写的人与读的人从未对齐过格式。
3. 这 32 条失配能长期存在，因为**唯一的质量信号是"页面能不能渲染"**，没有一条断言关心"诊断是否有内容"。V3 的 `probe-derived.mjs` 曾发现「challenger 有值但 0 引用」，那条告警本该扩大成常规门禁，但停在了单次探查。

## 8. 已知局限（必须随 spec 一起交付，不许省）

1. **多策略探针仍是有限策略集**，不能证明"所有玩家路径都被覆盖"，只能证明"至少 4 类典型策略下的表现"。
2. **行为派生带意图推断性质**：`*_obsession_count` 从 `expected_concerns_addressed` 反推玩家关注点，可能冤枉"随手点两下"的玩家。缓解：阈值 ≥2 次、文案用"倾向于"、必须可展开到具体回合。
3. **n=1 单用户，无统计功效**，任何前后对比只能作描述性陈述，不得写"提升 X%"。
4. **状态类原子的终局语义无法回溯时序**，这是数据模型决定的，M1 不改数据模型，只做标注。
5. **5 个场景即全部内容**，覆盖面窄于「认知偏见教育」的名义范围；这是产品定位问题，不在本次工程范围。
6. **未验证真实玩家体验**：所有结论来自代码与脚本，无一人次真实试玩记录。M0 产出前，不应对外声称任何教育效果。
